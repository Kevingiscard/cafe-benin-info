# Principes de finition utilisés pour Café Bénin

Cette note documente des principes généraux inspirés par trois projets publics, sans copier leur code, leur texte ou leurs assets.

## Emil Kowalski — design engineering

Le dépôt public met l’accent sur les détails invisibles, la précision des états, les animations justifiées, les courbes d’accélération naturelles et les interactions rapides. Pour Café Bénin, cela devient : animations d’interface sous 300 ms quand elles servent un retour utilisateur, états focus/active visibles, et aucune animation décorative indispensable à la compréhension.

Source : https://github.com/emilkowalski/skills

## Impeccable

Le projet propose de préserver le système existant, d’évaluer la hiérarchie, la typographie, la couleur, la motion, l’accessibilité, le responsive et les cas limites. Pour Café Bénin, cela devient : conserver la palette documentaire, formaliser les tokens dans DESIGN.md, traiter le site comme une expérience de lecture et vérifier les parcours à trois largeurs.

Source : https://github.com/pbakaus/impeccable

## Taste Skill

Le projet insiste sur une direction artistique choisie, les images réelles correctement créditées, une idée visuelle propre au projet et une vérification navigateur aux largeurs 1440, 768 et 390 px. Pour Café Bénin, cela devient : traiter le café comme un atlas documentaire, garder les crédits visibles, éviter les cartes génériques et vérifier le cadre, les marges, les images et les espaces vides.

Source : https://github.com/Leonxlnx/taste-skill

## Limite de réutilisation

Aucun code, fichier de skill, texte ou visuel de ces dépôts n’est copié dans le site. Seuls des principes de conception généraux et publiquement observables sont transposés dans une implémentation originale.
